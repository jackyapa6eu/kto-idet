# Проект: Кто идёт — Telegram-бот с мини-приложением

## Контекст
Форк проекта "ОПГ Здоровья" (см. `../obhg`) от 2026-09-07 — тот был
однотенантным ботом под конкретный чат (пляжный волейбол). "Кто идёт" —
попытка превратить ту же идею в продукт: инструмент для **любого**
Telegram-чата, где собираются на тренировки/игры/квизы и т.п., который
админ группы сам подключает себе. План превращения в мультитенантный
SaaS и продажи организаторам — в `README.md` (раздел Roadmap), там же
рыночное исследование и продуманный флоу онбординга. Оригинальный `obhg`
не трогаем — это отдельный, независимо работающий бот.

## Глобальная цель
Telegram-бот с мини-приложением (Mini App), где можно:
- создавать события (игра/тренировка/квиз: дата, время, место, макс. число участников и т.п.)
- записываться на события / отменять запись
- бот уведомляет записавшихся о статусе события (новое событие, изменения, напоминания)
- (см. Roadmap в README) — множество независимых групп на одном боте, у каждой свои настройки

## Стек
- **Frontend (Mini App):** React + TypeScript + Vite, Ant Design (UI), MobX (стейт-менеджмент). Папка `frontend/`.
- **Backend:** Hono на Node.js. Папка `backend/`. Отвечает за Telegram webhook, API для mini app, уведомления.
- **БД:** Neon Postgres (через Vercel Marketplace, нативная интеграция) + Drizzle ORM. Схема: `backend/src/db/schema.ts` (таблицы `users`, `login_sessions`, `events`, `participants`, `event_reminders`). Neon-проект называется `kto-idet-db` (Neon ID `mute-truth-42915562`, регион AWS us-east-1), план **Free** с самого создания (2026-09-07) — карта не привязана. Организация та же, что у `obhg`: `Vercel: jackyapa6eus-projects`. Открыть в Neon Console: Vercel → Storage/Integrations → Neon → `kto-idet-db` → "Open in Neon" (SSO).
- **Деплой:** Vercel — два отдельных проекта, **без Git-интеграции** (как и у `obhg` — пуш в GitHub не триггерит автодеплой, деплоить руками из соответствующей папки: `vercel --prod`):
  - `jackyapa6eus-projects/kto-idet-backend` (Hono + Neon подключён) → https://kto-idet-backend.vercel.app
  - `jackyapa6eus-projects/kto-idet-frontend` (Vite React) → https://kto-idet-frontend.vercel.app
- **GitHub:** https://github.com/jackyapa6eu/kto-idet (private, отдельная история — не форкнут через GitHub, а просто новый репозиторий с копией кода на момент 2026-09-07).
- **Telegram-бот:** @kto_idet_bot ("Кто идёт", grammY), вебхук зарегистрирован на `/api/telegram/webhook`, мини-апп зарегистрирован в BotFather (`/newapp`, short name `app`, `has_main_web_app: true`).
- **Домен:** свой домен подключим позже.
- **Авторизация:** тот же механизм, что в `obhg` — без изменений:
  - Внутри мини-аппа — Telegram-идентификация через `initData` (проверяется на бэкенде HMAC-подписью с `TELEGRAM_BOT_TOKEN`, см. `backend/src/telegramAuth.ts`). При каждом заходе апсертится строка в `users` (имя/аватар обновляются, см. `backend/src/users.ts`).
  - Вне мини-аппа (обычный браузер) — вход через **редирект в бота** (`frontend/src/components/TelegramBotLoginButton.tsx`), без номера телефона и SMS вообще: фронт создаёт одноразовую сессию (`POST /api/auth/session` → таблица `login_sessions`), открывает пользователю `t.me/kto_idet_bot?start=login-<token>`, пользователь жмёт Start в уже залогиненном Telegram-приложении, бот (`backend/src/bot.ts`, обработчик `/start`) подтверждает сессию его telegramId, а фронт всё это время поллит `GET /api/auth/session/:token` (раз в 2 сек, TTL сессии — 10 минут). После подтверждения бэкенд выдаёт JWT (30 дней, `hono/jwt`, секрет — `JWT_SECRET`) и удаляет сессию (одноразовая). Фронт хранит JWT в `localStorage`, шлёт `Authorization: Bearer <jwt>` (см. `frontend/src/api.ts`).
  - Все защищённые ручки (`POST /api/events`, `GET /api/auth/me`) принимают либо `X-Telegram-Init-Data`, либо `Authorization: Bearer` — `createdByTelegramId` всегда берётся из проверенных данных, клиент не может его подделать.
  - `JWT_SECRET` и `CRON_SECRET` сгенерированы заново для этого проекта (2026-09-07) и добавлены в Vercel env (все окружения — Production/Preview/Development) — не переиспользуют секреты `obhg`.
- Бюджет: максимально бесплатные тиры (Vercel Hobby, Neon free tier) — актуально ещё сильнее, чем для `obhg`, пока это pre-revenue продукт.

## Заметки / решения
- Frontend и backend — сознательно раздельные проекты (не Next.js монолит), унаследовано из `obhg`.
- Backend-фреймворк — Hono, унаследовано из `obhg`.
- В `package.json` backend уже стоит проверенная стабильная `typescript@5.9.3` (в исходном шаблоне Hono была прибита `^7.0.2`, которая падала именно на билд-машине Vercel — `obhg` это уже поймал и пофиксил, здесь фикс просто унаследован). Если снова столкнёмся с непонятными крашами сборки только на Vercel — сначала проверять версию TypeScript.
- Токен бота проверен через `getMe()` перед тем, как прописывать в env (сразу после создания в BotFather) — рабочий, в отличие от истории с `obhg`, где локальный токен на каком-то этапе был невалиден. Если бот перестанет отвечать — первым делом `curl https://api.telegram.org/bot<TOKEN>/getMe`.
- `getBotUsername()` в `backend/src/bot.ts` — статичное значение (env `TELEGRAM_BOT_USERNAME`, сейчас `kto_idet_bot`), не живой вызов `getMe()` — см. обоснование в `obhg`.
- **Напоминания о событиях** (`backend/src/reminders.ts`, `sendDueReminders`) рассчитаны на внешний крон, дёргающий `POST /api/cron/reminders` раз в 30 минут (окно напоминания — 30–90 минут до начала, шире шага крона специально, чтобы пропуск одного прогона не терял событие) — **для kto-idet этот крон ещё не заведён**, нужно будет создать job на cron-job.org, когда дойдём до реального тестирования уведомлений.
- **Урок из инцидента `obhg` (Neon compute quota, август 2026):** если позже настраивать крон чаще раза в 30 минут — сначала проверить `Scale to zero` компьюта в Neon (там таймер простоя перед сном, по умолчанию около 5 минут) — слишком частый крон не даёт БД засыпать и сжигает бесплатную квоту CU-часов за считанные дни. Подробности разбора инцидента — в `obhg/CLAUDE.md`, если понадобится точная хронология.
