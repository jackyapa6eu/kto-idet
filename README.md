# Кто идёт

Telegram-бот с мини-приложением для организации сборов в групповых чатах: тренировки, игры, квизы. Админ подключает бота к своей группе, участники записываются в один клик, а бот сам ведёт сводку и напоминает о событиях.

Бот: [@kto_idet_bot](https://t.me/kto_idet_bot) · Сайт: [kto-idet.ru](https://kto-idet.ru)

Проект вырос из бота, который я сделал для своей группы по пляжному волейболу. Здесь та же идея доработана так, чтобы её мог подключить любой организатор.

## Возможности

**Для участников**
- Список мероприятий группы прямо в Telegram, без установки приложений
- Запись и отмена записи, лимит мест и резерв: при освобождении места первый из резерва автоматически попадает в основной состав
- Напоминание перед началом события с упоминанием записавшихся
- Прямая ссылка на мероприятие, которая открывает мини-приложение сразу на нём
- Вход и через мини-приложение, и через обычный браузер, поддержка тёмной темы Telegram

**Для организаторов**
- Подключение без помощи разработчика: пошаговый мастер настройки в личке с ботом
- Закреплённая сводка мероприятий в чате, которая обновляется при каждой записи и отмене
- Анонсы новых событий в выбранный топик группы
- Отметки оплаты и исключение участников
- Шаблоны мероприятий для быстрого создания и повторяющиеся события
- Настройки группы: название, включение оповещений, право участников создавать мероприятия
- Меню в личке с ботом для тех, кто ведёт несколько групп
- Если бота удалили из группы, данные хранятся 14 дней и восстанавливаются при возврате

## Стек

**Frontend (Mini App):** React, TypeScript, Vite, MobX, Ant Design

**Backend:** Node.js, Hono, grammY (Telegram Bot API)

**База данных:** PostgreSQL (Neon), Drizzle ORM

**Инфраструктура:** Vercel, вебхук Telegram, внешний крон для напоминаний и повторов

## Интересные решения

- **Мультитенантность.** Один бот обслуживает много независимых групп. Данные и права разделены по организациям, членство и права админа проверяются через Telegram API для каждой группы.
- **Авторизация без паролей и SMS.** В мини-приложении пользователь определяется по `initData`, подпись проверяется на бэкенде через HMAC. В браузере вход идёт через бота: фронт создаёт одноразовую сессию, пользователь нажимает Start в Telegram, бот подтверждает сессию, и фронт получает JWT.
- **Защита от подмены данных.** Автор события всегда берётся из проверенных данных Telegram, а не из запроса клиента.
- **Сводка без спама.** Бот не шлёт новое сообщение на каждое изменение, а редактирует одно закреплённое. Навигация в личке тоже работает в одном сообщении через callback-кнопки.
- **Устойчивые напоминания.** Окно напоминания шире шага крона, поэтому пропущенный запуск не теряет событие. Ошибки Telegram не ломают основную операцию: запись сохраняется, даже если сводку обновить не удалось.

## Структура

```
backend/    Hono API, Telegram-бот, схема БД и кроны
frontend/   Mini App на React
```

## Локальный запуск

```bash
# backend
cd backend
npm install
npm run db:push   # применить схему БД
npm run dev

# frontend
cd frontend
npm install
npm run dev
```

Бэкенд читает переменные из `backend/.env.local`: токен бота, строка подключения к БД, `JWT_SECRET`, `CRON_SECRET`.
